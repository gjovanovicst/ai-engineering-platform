# 19 · Accessibility audit

Standard: **WCAG 2.1 AA** for the app shell, forms, dialogs and data views.
Method: code review of every page plus a manual keyboard pass. Automated
checks are not in CI yet (see §5).

## 1. Findings and fixes

| # | Finding | Severity | Fix |
|---|---|---|---|
| F1 | The header search was a `div` that looked interactive (with a fake ⌘K hint) but did nothing | high (affordance lies) | replaced with a link to `/search` and `aria-label="Search tasks"` |
| F2 | `aria-current="page"` was hardcoded to the second nav item | high (screen-reader lie) | computed from `usePathname()`; nested routes count as active |
| F3 | No skip link; keyboard users had to tab through the whole sidebar | medium | "Skip to content" link, visible on focus, target `#main-content` |
| F4 | Task drawer opened without moving focus, and its name came from `aria-label` only | medium | focus moves to the close button; `aria-labelledby` points at the task title |
| F5 | Five sidebar entries pointed at `/projects` ("AI Agents", "Design System", "Components", "Environments", "Repositories") | high (broken promises) | removed until the pages exist |
| F6 | `Button` defaulted to `type="submit"`; a button inside a form could submit by accident | medium | defaults to `type="button"`; all 7 forms set `type="submit"` explicitly |
| F7 | No global focus style outside components | medium | `:focus-visible` outline using the brand token in `globals.css` |
| F8 | Icon-only buttons (notifications) had no accessible name | low | `aria-label="Notifications"` already present; kept and documented |

## 2. Page checklist

| Area | Keyboard | Names/roles | States | Notes |
|---|---|---|---|---|
| Login / register | tab order, Enter submits | labels tied via `Field`, errors `role="alert"` | inline errors announced | OIDC buttons are real links |
| Projects list | cards are links | headings h1/h2 | loading skeleton, empty, error with retry | |
| Project detail | task title is a button | drawer `role="dialog" aria-modal` | all four states | drawer closes on Escape |
| Task drawer | focus on close, Escape closes | `aria-labelledby` title | run timeline is a list | no full focus trap (§4) |
| Run page | links to PRs, buttons | status is text, log rows are text | plan/diff/review panels | log auto-scroll does not steal focus |
| Approvals | Approve/Reject reachable | confirmation banner `text-status-success` | reason required on reject | |
| Blueprints wizard | Back/Continue, step indicator is text | `ol` with labels | review summary is a list | step count announced as text |
| Analytics | read-only | metric cards use headings | `source: na` explained | bars have text values |
| Settings / invites | form labels | link copied via selectable text | pending/accepted text | |

## 3. Colour and motion

- All component colours come from design tokens (`make pilot-check` rejects raw
  hex in `components/`).
- Contrast was checked visually against the token palette (text-primary on
  bg-surface, text-secondary on bg-surface, status colours on their 10%
  backgrounds). Not measured programmatically — see §5.
- No animations except hover transitions and the loading skeleton (pulse);
  `prefers-reduced-motion` is not handled yet.

## 4. Known gaps

1. ~~No focus trap in the task drawer~~ — fixed: Tab cycles inside the panel,
   Escape closes, focus returns to the trigger on unmount.
2. ~~No automated axe-core run in CI~~ — fixed: `src/a11y.test.ts` runs axe
   against the prerendered login/register/404 HTML in the web CI job (build
   before test).
3. **Contrast is not machine-verified.** jsdom has no layout, so
   `color-contrast` is disabled in the axe run; add `@axe-core/playwright` for a
   real-browser contrast check.
4. **Icons are text glyphs** (⌕, ◈) with `aria-hidden`; they have no accessible
   name of their own, which is intended — the label is adjacent text.
5. **Zoom at 200%** was not tested on a real device.

## 4a. Running the axe test locally

`src/a11y.test.ts` reads the prerendered HTML, so it needs a production build:

```bash
# stop `next dev` first: dev and build must not share .next
pnpm build && pnpm test
```

Never run `pnpm build` while `next dev` is serving the app; the dev server then
references CSS chunks that the build replaced and pages load unstyled.

## 5. Manual test script (run before a pilot)

1. Keyboard only: Tab from the top; the skip link appears first and jumps to
   the main region. No focus trap outside the drawer.
2. Open a project → task drawer: focus lands on Close, Escape closes, focus
   returns to the task title (browser default for the trigger button).
3. Screen reader (VoiceOver/NVDA): each page announces one h1, the nav marks
   the current page, form errors are read when they appear.
4. Zoom to 200% at 1280px width: no horizontal scrolling on the project page.
5. Run the colour-contrast check on text-secondary over bg-surface and on
   status colours over their tinted backgrounds.
