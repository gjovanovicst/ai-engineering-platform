# 13 · Project setup — decisions before the first commit

Everything that must be fixed so that `E1-S1` does not start with improvisation. Changing these
things after the first commit costs; that is why they are here, and not in someone's head.

## 1. Project identity

| Item | Value | Note |
|---|---|---|
| Repo | `ai-engineering-platform` | monorepo (see [ADR-0001](adr/README.md#adr-0001--backend-in-go)) |
| Go module | `github.com/gjovanovicst/ai-engineering-platform` | **the only change before the first `go mod init`** if the GitHub org changes |
| Default branch | `main` | protected; no direct push (for agents either) |
| API version | `v1` | in the `/api/v1` path |
| License | Apache-2.0 | see `LICENSE`; contributions under DCO |

Branch protection on `main`:

- require PR (1 approval), require `make check` (CI), require linear history,
- no force-push, no deletion, admin bypass only for `goran`.

## 2. Environments

| Environment | API | Web | Database | S3 | Email |
|---|---|---|---|---|---|
| **local** | `localhost:18080` | `localhost:3000` | `localhost:5432` | MinIO `:9000` | Mailhog `:8025` |
| **staging** | `api.staging.aip.local` | `app.staging.aip.local` | managed Postgres 17 | MinIO/S3 | Postmark sandbox |
| **prod** | `api.aip.local` | `app.aip.local` | managed Postgres 17 (HA) | S3 | Postmark |

The domains are placeholders — replacing them before the staging deploy is one `.env`. Staging is
**a single VPS + docker compose** until M5; K8s only when the `E10-S4` load test shows the need (ADR).

## 3. Services in `docker-compose.yml` (local)

| Service | Image | Port | Why |
|---|---|---|---|
| `postgres` | `postgres:17-alpine` | 5432 | state + queue (River) |
| `redis` | `redis:7-alpine` | 6379 | SSE fanout, rate limit, revocation |
| `minio` | `minio/minio` | 9000/9001 | artifacts (diff, log, plan) |
| `mailhog` | `mailhog/mailhog` | 1025/8025 | email in dev |
| `aipd` | build `apps/api` | 18080 (host) / 8080 (container) | API |
| `aip-worker` | build `apps/api` | — | agent runtime |
| `web` | `web/Dockerfile` (dev target) | 3000 | Next.js |

`make dev` brings up everything except the database/redis (which are kept running by `docker compose up -d postgres redis minio mailhog`).

AIP_HTTP_ADDR=:18080
AIP_BASE_URL=http://localhost:18080
AIP_WEB_URL=http://localhost:3000

# ── database and queue
AIP_DB_DSN=postgres://aip:aip@localhost:5432/aip?sslmode=disable
AIP_DB_MIGRATOR_DSN=postgres://aip_migrator:aip@localhost:5432/aip?sslmode=disable
AIP_REDIS_ADDR=localhost:6379

# ── auth
AIP_JWT_KEY=                       # PEM (Ed25519); generated by `make keygen`
AIP_ACCESS_TTL=15m
AIP_REFRESH_TTL=720h
AIP_COOKIE_DOMAIN=localhost
AIP_OIDC_GITHUB_CLIENT_ID=
AIP_OIDC_GITHUB_CLIENT_SECRET=

# ── email
AIP_MAILER=mailhog                 # mailhog | postmark | ses

# ── objects

AIP_S3_SECRET_KEY=minio123

# ── sandbox

AIP_SANDBOX_EGRESS_ALLOW=proxy.golang.org,registry.npmjs.org,api.github.com

# ── agent
AIP_AGENT_BACKEND=tools            # command | provider | tools

# ── git providers

GITLAB_TOKEN=

AIP_GITHUB_APP_INSTALL=             # optional; first installation is used

Rules:

- Everything from env, `AIP_` prefix, validation at startup (fail fast with a list of problems).
- `AIP_*_KEY`, `*_SECRET`, `*_PASSWORD` are **never** logged; `config.String()` redacts them.
- `.env` is in `.gitignore`; `.env.example` is the source of truth for the names.

## 5. Secrets

| Environment | Storage |
|---|---|
| local | `.env` (gitignored) |
| CI | GitHub Actions secrets |
| staging/prod | Vault or SealedSecrets; only `secret_ref` in the database |

Provider keys entered by the user go into `ai_providers.secret_ref` → secrets store;
the API never returns the value (`has_key: true`).

## 6. Email

- Dev: Mailhog, no authentication; links in the email point to `localhost:3000`.
- Prod: Postmark, verified domain (SPF/DKIM/DMARC), `no-reply@<domain>`.
- Templates in `internal/platform/mail/templates/*.html.tmpl` (embed); the text version is required.

## 7. GitHub integration

- **GitHub App** (not a PAT) — installed per org, `installation_id` in `repos`.
- Permissions: `contents:read/write`, `pull_requests:write`, `checks:write`, `metadata:read`.
- Webhook secret in env; verification of `X-Hub-Signature-256` (HMAC, constant-time).
- For the first spike (M2) a PAT is allowed **only** locally, never in a commit.

## 8. Backlog (while the platform does not exist)

Stories live in **GitHub Issues**, with labels the agent can filter:

| Label | Meaning |
|---|---|
| `epic:e1` … `epic:e10` | epic membership from [05-mvp-plan.md](05-mvp-plan.md) |
| `ready` | DoR met → the agent may take it |
| `agent:go` / `agent:web` | which part of the repo |
| `blocked` | waiting on a decision/dependency |
| `p0` / `p1` / `p2` | priority |
| `spike` | time-boxed investigation, does not go into `main` without an ADR |

Detailed story pickup rules: [AGENTS.md §9](../AGENTS.md#9-backlog-how-an-agent-picks-up-a-story).

New stories use the **Story** issue template (`.github/ISSUE_TEMPLATE/story.yml`),
which encodes the Definition of Ready. Create or update the labels with
`make labels` (`scripts/sync-labels.sh`; the token needs **Issues: write**).

## 9. Definition of "ready for the first commit"

- [ ] `go mod init github.com/gjovanovicst/ai-engineering-platform` (or the agreed path)
- [ ] `.gitignore` (Go, Node, `.env`, `/dist`, `coverage`)
- [ ] `.editorconfig`, `.golangci.yml`, `web/.eslintrc` + `prettier`
- [ ] `Makefile` with `build test lint check dev migrate-up seed keygen`
- [ ] `docker-compose.yml` (§3) + `.env.example` (§4)
- [ ] `apps/api/migrations/0001_init.sql` (orgs/users/memberships/sessions/invites)
- [ ] `.github/workflows/ci.yml` (`make check`, openapi-diff, trivy)
- [ ] `web/` initialized (Next 15, TS strict, Tailwind with tokens)
- [ ] `docs/` linked from the README; `AGENTS.md` in place

When these 9 boxes are checked, `E1-S1` is complete and `E1-S2` can start.
