# v0.1.1 — 2026-11-18

**The self-hosting readiness release.**

The agent loop now fixes itself: a failed run can be retried with its approved
plan, review blockers and failed CI checks become fix runs on the same pull
request, and the test gate follows the project instead of the environment. A
fresh install can start with real demo data.

## Highlights

- **Retry with the same plan**: a failed development run can be retried with
  its approved plan — no planning run and no new approval. The failure panel
  gains **Retry development**; a `run.retried` event records the source run.
- **Per-project test command**: `projects.test_command` overrides the global
  `AIP_TEST_COMMAND` (a Go API + Node web repository needs both toolchains in
  one gate). Delivery → Checks gains the field; the API exposes
  `PUT /orgs/{org}/projects/{project}/test-command`.
- **Web dependencies in the offline sandbox**: when a repository has
  `pnpm-lock.yaml` (root or `apps/web/`), the worker installs the locked
  dependencies on the host (`pnpm install --frozen-lockfile --ignore-scripts`)
  and the sandbox receives `node_modules`; a `dependency.fetch` run event
  records it. `AIP_DEPS_NPM` (default on) and `AIP_PNPM_BIN` control it.
- **Review-fix runs**: a review with blocker findings gains **Fix review
  findings**. The fix keeps the approved plan and the pull-request branch, so
  the existing PR updates and the review re-runs.
- **CI-fix runs**: a failed check gains **Fix CI**. The GitHub Actions job log
  is fetched on the host with the repository token and becomes the fix prompt;
  the PR updates and the checks re-run.
- **`aipctl seed`**: creates the demo org **Acme**, the owner `demo@acme.io`
  (password from `AIP_SEED_PASSWORD`), the **Demo** project and three ready
  tasks with acceptance criteria. Idempotent; `make seed` is in the quickstart.
- **README and documentation**: a banner, a quickstart-first README and a
  complete documentation index.
- **Clean dependency audit**: vitest 4.1.12, vite 6.4.6 and the minimatch
  update; `pnpm audit` reports zero advisories.

## Upgrading from v0.1.0

```sh
git pull
make migrate-up      # applies 0079, 0080, 0081
```

- Migrations: `0079` (`projects.test_command`), `0080` (`runs.fix_of_run_id`),
  `0081` (`runs.fix_kind`, `runs.fix_context`). All additive.
- New environment variables: `AIP_DEPS_NPM` (default `true`) and
  `AIP_PNPM_BIN` (default `pnpm`). Set `AIP_DEPS_NPM=false` to keep the old
  behaviour.
- `AIP_TEST_COMMAND` still works as the fallback when a project has no test
  command.

## Images

```
ghcr.io/gjovanovicst/ai-engineering-platform/api:v0.1.1
ghcr.io/gjovanovicst/ai-engineering-platform/web:v0.1.1
ghcr.io/gjovanovicst/ai-engineering-platform/sandbox:v0.1.1
```

The sandbox image is required for agent runs:

```sh
AIP_SANDBOX_IMAGE=ghcr.io/gjovanovicst/ai-engineering-platform/sandbox:v0.1.1
```

The web image inlines `NEXT_PUBLIC_API_URL` at **build** time. The release
workflow reads the repository variable `AIP_WEB_API_URL`; set it to the URL your
browser uses for the API before tagging a release.

## Known limits

- **Developer preview**: self-hosted only; there is no hosted SaaS. Multi-tenant
  isolation, abuse controls and support are out of scope for v0.1.
- **An LLM provider key is required** for agent runs (`AIP_PROVIDER_*`).
- **The worker needs the Docker socket** to run the sandbox image, and `pnpm`
  on the host for the web dependency preparation.
- **The seed's default password is local only**; set `AIP_SEED_PASSWORD` for
  anything beyond a local demo.
- **The CI-fix log fetch is GitHub Actions only**: another provider, a fetch
  failure or a check without a job URL falls back to the check output.
- **Fix runs need a repository credential** with Contents and Pull requests
  read/write (the same PAT scopes as the publisher).
- **The platform never merges on its own**: a human approves the PR; branch
  protection should require the same checks.
